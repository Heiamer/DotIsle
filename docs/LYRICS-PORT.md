# 在线歌词链路

当前自动检索使用 H0308/taskbar-lyrics-displayer 提交 `3fae9287dfb0636fc19a0df2587a1a59a54cf9bb` 的规则，移植为 Go/Rust。源文件摘要记录在 LYRICS-UPSTREAM.json；Apache-2.0 原许可及修改声明随附于 licenses。

播放器读取继续使用点屿现有的 SMTC 与网易云适配。播放器品牌不是歌词源限制：通用播放器、浏览器和本地播放器有媒体信息时，共用同一在线链路。播放器身份仅用于网易云歌曲 ID 和汽水试听优先分支；不会把其他播放器限制为同名歌词源。

保留点屿的用户映射、本地歌词与最终缓存，在线部分按以下顺序执行：

1. 网易云播放器有歌曲 ID 时优先直接请求；汽水播放器先按原始元数据匹配汽水。
2. 酷狗 KRC → QQ QRC → QQ LRC → LRCLIB → 网易云元数据 → 汽水元数据。跳过已经在播放器专属分支试过的来源。
3. QQ QRC 与 LRC 共用每个变体的同一份候选。酷狗成功后按上游规则补取 QQ 次要文本。
4. 搜索词按原文、Windows 简体、规范化、主要歌手、剥离版本后缀及相应简体变体生成。所有候选仍与原始元数据评分。阈值 80、版本标签一致和 15 秒时长排除均来自该提交。
5. QQ/网易云/汽水次要文本采用上游的单调最近时间点、1500 毫秒容差、仅填空规则。保留音译字段，现有界面继续显示原文与翻译。
6. 网易云 YRC 失败回退 LRC；酷狗解密 KRC；QQ 解密 QRC；LRCLIB 支持同步 LRC 和有逐字标记的 lyricsfile；汽水保留完整时间轴与试听对齐。

所有歌词网络请求直连，Go Transport 的 Proxy 为 nil。酷狗保留上游的三个 HTTP 接口；其余使用来源自己的 HTTPS 接口。没有歌词代理、转发服务、Java 进程或 JRE 依赖。HTTP 域名及酷狗 HTTP 路径限定为所需接口。请求 User-Agent 标识点屿；系统显示时间轴、缓存、本地文件与本机媒体适配使用点屿自己的模型。

## 验证与打包

`lyrics/testdata/taskbar-parity.json` 包含从原始 C++ 匹配实现生成的 1200 组分数与完整查询变体列表，Go 测试逐项比较。源请求、排序和过滤以 HTTP fixture 检查；Rust 测试覆盖顺序回退、无效逐字解析后的回退、候选复用与解析细节。

`verify_online_modules` 经真实 DLL ABI 发起异步任务，再经过 Go 工作进程和实际网络，最后调用显示时间轴。`verify_online_pipeline` 使用隔离的系统媒体会话，经过正式媒体读取、歌词模块与显示帧，并检查跳转与切歌。它们是指定样本验证，不能推导全曲库准确率或所有第三方播放器版本兼容性。

正式产物必须先运行 `tools/li-cargo.ps1 build --release --workspace --offline`，再单独构建所需 examples。`--examples` 只更新诊断可执行文件及其链接代码，不能作为正式 cdylib 已更新的依据。

打包器先调用 `build/verify_lyrics_engine.py`，核对正式歌词 DLL 的引擎与提交标识，并启动正式 Center 检查 taskbar 工作进程协议，拒绝旧 DLL 或不配套的 Go 程序。最终还需对打包目录执行在线模块及播放器链路测试。

旧在线检索、评分、下载分支及其工作进程操作已删除。歌曲时长补取通过同一 taskbar 元数据适配器查询；保留本地歌词、用户映射和显示时间轴。
